## Архитектура (см. диаграмму)

Ответы на вопросы:

### Представление данных

- **TrackedFile** — отслеживаемый файл: путь, хэш, статус.
- **Commit** — включает ID, автора, дату, сообщение, ссылку на родителя(ей), список изменений.
- **Branch** — имя и указатель на последний коммит.
- **Repository** — содержит ветки, текущую HEAD-ссылку, объекты и настройки.

### Компрессия и доступ к версиям

- Используются снапшоты или дельты файлов.
- История коммитов связана через родительские ссылки.
- Быстрый доступ к любому состоянию через индекс и кэш.

### Жизненный цикл файла

1. Создание/изменение файла в рабочем каталоге.
2. Добавление в индекс (`add`).
3. Сохранение в коммит (`commit`).
4. Возможность восстановления, удаления, слияния и отслеживания изменений.

### Работа с файловой системой

- Хранилище `.vcs/`:
  - объекты (`objects/`)
  - индекс
  - HEAD и ссылки на ветки
- Взаимодействие через абстракцию `FileSystemManager`.

### Взаимодействие с пользователем

- Python-Библиотека с классом `Repository`, как входная точка.
- CLI-интерфейс (команды: `commit`, `log`, `merge`, `branch`, `checkout`, и др.)
- Обработка ошибок и подсказки

### Работа с удалёнными репозиториями

- **RemoteClient** — команды: `clone`, `fetch`, `pull`, `push`.
- **RemoteRepository (server)** — API для хранения коммитов, веток и файлов.
- Протокол синхронизации по хэшу: передаются только отсутствующие объекты.
